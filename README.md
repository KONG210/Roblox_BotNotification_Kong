# Anime Adventures Farm Dashboard

เว็บแดชบอร์ดติดตามการฟาร์มแมพของเกม Roblox **Anime Adventures** แบบเรียลไทม์
อ่านรายงานที่สคริปต์ Roblox ส่งเข้า Discord (ผ่าน Webhook) แล้วเก็บลงฐานข้อมูล PostgreSQL
จากนั้นแสดงเป็นหน้าเว็บมืด หน้าเดียว มีไทม์ไลน์รอบที่เล่น ยอดคงเหลือ และอัตราฟาร์มต่อชั่วโมง

- เว็บจริง: https://roblox-botnotification-kong.onrender.com/ (ต้องล็อกอิน)
- โค้ด: https://github.com/KONG210/Roblox_BotNotification_Kong

## 1. ภาพรวมการทำงาน

```
สคริปต์ Roblox ──Webhook──▶ ห้อง Discord ──Bot อ่านข้อความ──▶ server.js ──▶ PostgreSQL
                                                                  │
                                              Socket.IO / REST API│
                                                                  ▼
                                                       เบราว์เซอร์ (public/)
```

> ทำไมต้องมี Bot อ่านห้อง Discord: บอทฟาร์มรับได้เฉพาะ Discord Webhook URL จึงส่งข้อมูลเข้าเว็บโดยตรงไม่ได้
> ต้องให้ Webhook โพสต์ลงห้อง แล้วให้ Bot อีกตัวอ่านข้อความจากห้องนั้นมาเก็บ

1. สคริปต์ในเกมส่งรายงานจบรอบ (ชนะ/แพ้ แมพ รางวัล ยอดคงเหลือ) เข้าห้อง Discord ผ่าน Webhook
2. Discord Bot (อ่านห้องเดียวกัน) รับข้อความใหม่ทันที และตอนเริ่มระบบจะอ่านย้อนหลังสูงสุด 1,000 ข้อความ (10 หน้า × 100)
3. `server.js` แยกข้อมูลออกจากข้อความ แล้วบันทึกลงตาราง `runs` (กันซ้ำด้วย id ของข้อความ)
4. เมื่อมีรอบใหม่ เซิร์ฟเวอร์ส่งสัญญาณ `updated` ผ่าน Socket.IO หน้าเว็บจึงโหลดข้อมูลใหม่ทันที
   (และมีรีเฟรชสำรองทุก 60 วินาที เผื่อ WebSocket ใช้ไม่ได้)

## 2. ฟีเจอร์

**แถบด้านซ้าย**
- สถานะการเชื่อมต่อ และชื่อผู้เล่นล่าสุด
- ตัวบอกอายุรายงานล่าสุด เช่น "รายงานล่าสุด 2 นาทีที่แล้ว" เปลี่ยนเป็นสีแดง "⚠ ไม่มีรายงานมา" เมื่อเงียบเกิน **40 นาที** (น่าจะหยุดฟาร์ม)
- 4 ช่องหลัก: **เพชร / ทอง / SummerPearls / Trait Reroll** แสดงยอดคงเหลือล่าสุดตามที่ Discord รายงาน
- อัตราชนะ, จำนวนรอบทั้งหมด, ชนะ, แพ้
- อัตราฟาร์มต่อชั่วโมง (รอบ/ชม. และของแต่ละชนิด/ชม.)
- กราฟผลการเล่น 40 รอบล่าสุด
- "ของที่ได้ทั้งหมด": รางวัลสะสมของไอเทมอื่น ๆ (ซ่อนเองถ้าไม่มี)
- ปุ่มล้างประวัติทั้งหมด

**ไทม์ไลน์ด้านขวา**
- การ์ดแต่ละรอบ: เวลา, ผลชนะ/แพ้, ชื่อแมพ + รูปแมพ, โหมด (Raid/Story/...), ความยาก, เวฟ, เวลาที่ใช้, รางวัลพร้อมไอคอน
- จัดกลุ่มตามวัน
- ค้นหาตามชื่อแมพ/ผู้เล่น และกรองชนะ/แพ้
- ซ่อนรอบ `Test notification` และรอบที่อ่านชื่อแมพไม่ได้ (`Unknown`) จากไทม์ไลน์ (ดูหัวข้อ 8)

หน้าเว็บรองรับมือถือ (จอแคบกว่า 900px จะเรียงเป็นคอลัมน์เดียว)

## 3. โครงสร้างโปรเจกต์

```
.
├── server.js            แบ็กเอนด์ทั้งหมด (Express + Socket.IO + Discord + PostgreSQL)
├── package.json         dependencies และคำสั่ง npm start
├── render.yaml          ค่า deploy สำหรับ Render
├── .env.example         ตัวอย่างค่าที่ต้องตั้ง (ห้ามใส่ค่าจริงในไฟล์นี้)
├── .gitignore
└── public/              ไฟล์หน้าเว็บ (เสิร์ฟเป็น static)
    ├── index.html       โครงหน้า
    ├── style.css        สไตล์ (ธีมมืด)
    ├── app.js           ลอจิกหน้าเว็บ (ไม่ได้บีบอัด แก้ได้ตรง ๆ)
    └── assets/
        ├── items/       ไอคอนไอเทมจากวิกิ + manifest.json
        ├── maps/        รูปแมพจากวิกิ + manifest.json
        └── *.svg        ไอคอนสำรอง (fan-made) ใช้เมื่อไม่มีรูปจากวิกิ
```

ไฟล์ที่มักต้องแก้:
- เปลี่ยนการอ่านข้อความ Discord → `parseMessage()` ใน `server.js`
- เปลี่ยนหน้าตา → `public/style.css`
- เปลี่ยน 4 ช่องหลัก → ตัวแปร `slots` ใน `public/app.js`
- ปรับเวลาเตือนเงียบ → `STALE_MIN` ใน `public/app.js`

## 4. ตั้งค่า (Environment Variables)

| ตัวแปร | จำเป็น | ความหมาย |
|---|---|---|
| `DISCORD_BOT_TOKEN` | ใช่ | โทเค็นของ Discord Bot ที่อ่านห้องรายงานได้ |
| `DISCORD_CHANNEL_ID` | ใช่ | ID ห้องที่ Webhook ส่งรายงานเข้า |
| `DISCORD_WEBHOOK_ID` | ไม่ | ถ้าตั้ง จะรับเฉพาะข้อความจาก Webhook ตัวนี้ (กรองสแปม/Webhook อื่น) |
| `DATABASE_URL` | ใช่ | connection string ของ PostgreSQL |
| `DATABASE_SSL` | ไม่ | `true` (ค่าเริ่มต้น) หรือ `false` สำหรับ DB ในเครื่องที่ไม่มี SSL |
| `DASHBOARD_PASSWORD` | ใช่ | รหัสผ่านเข้าเว็บ (ผู้ใช้คือ `admin`) |
| `PORT` | ไม่ | พอร์ตเซิร์ฟเวอร์ (ค่าเริ่มต้น 3030; Render ตั้งให้เอง) |

**ใช้ Supabase เป็นฐานข้อมูล:** ใช้ connection string แบบ **Session Pooler** (รองรับ IPv4) ไม่ใช่ Direct connection
เพราะ Render เชื่อมต่อผ่าน IPv4 และคงค่า `DATABASE_SSL=true`

ถ้าขาดตัวที่ "ใช่" ตัวใดตัวหนึ่ง เซิร์ฟเวอร์จะไม่เริ่มและแจ้งข้อผิดพลาดทันที

**เรื่อง `DISCORD_WEBHOOK_ID`:** ถ้าเปลี่ยน Webhook ใหม่แล้วข้อมูลไม่ขึ้น ให้ตรวจว่าค่านี้ตรงกับ Webhook ปัจจุบัน
ค่าเก่าจะทำให้ข้อความจาก Webhook ใหม่ถูกกรองทิ้งเงียบ ๆ (ลบตัวแปรนี้ทิ้งได้ถ้าไม่ต้องการกรอง)

**วิธีหา ID:** ใน Discord เปิดโหมดนักพัฒนา (Settings → Advanced → Developer Mode)
แล้วคลิกขวาที่ห้อง → Copy Channel ID ส่วน Webhook ID คือตัวเลขชุดแรกใน URL ของ Webhook
(`https://discord.com/api/webhooks/<WEBHOOK_ID>/<TOKEN>`)

**สิทธิ์ของ Bot:** ต้องเปิด **Message Content Intent** ที่ Discord Developer Portal และให้ Bot เห็น/อ่านประวัติข้อความในห้องรายงาน

## 5. รันในเครื่อง

ต้องมี Node.js 20 ขึ้นไป และ PostgreSQL ที่เข้าถึงได้

```bash
npm install
cp .env.example .env     # แล้วแก้ค่าใน .env
npm start
```

เปิด http://localhost:3030 ล็อกอินด้วยผู้ใช้ `admin` และรหัสผ่านจาก `DASHBOARD_PASSWORD`

ถ้า PostgreSQL ในเครื่องไม่ใช้ SSL ให้ตั้ง `DATABASE_SSL=false`
ตารางถูกสร้างอัตโนมัติตอนเริ่ม (`runs` และ `meta`) ไม่ต้องรัน SQL เอง

## 6. Deploy บน Render

1. push โค้ดขึ้น GitHub (branch `main`)
2. บน Render สร้าง Web Service จากรีโป หรือใช้ `render.yaml` (Blueprint) ในรีโปนี้
3. ตั้ง Environment Variables ตามหัวข้อ 4 (ค่าที่เป็นความลับตั้งในหน้า Render ไม่ใส่ในไฟล์)
   - ระวังพิมพ์ชื่อตัวแปรผิด เช่น `NODE_ENV` เคยพิมพ์ตกเป็น `ODE_ENV`
   - ช่อง Root Directory เว้นว่างไว้ เพราะ `package.json` อยู่ที่รากของรีโป
4. Render จะ build ด้วย `npm install` และเริ่มด้วย `npm start` โดยเช็คสุขภาพที่ `/health`
5. หลังจากนี้ทุกครั้งที่ push เข้า `main` Render จะ deploy อัตโนมัติ (หรือกด Manual Deploy → Deploy latest commit)

หมายเหตุ Render แพ็กเกจ Free: เซิร์ฟเวอร์จะหลับเมื่อไม่มีคนเข้าใช้ ครั้งแรกที่เปิดอาจรอสักครู่
และระหว่างหลับ Bot จะไม่รับข้อความ แต่พอตื่นขึ้นมาระบบจะอ่านย้อนหลังจากห้อง Discord ให้เอง
(เพราะอ่านย้อนได้สูงสุด 1,000 ข้อความ ถ้ามีรายงานมากกว่านั้นระหว่างหลับ ส่วนที่เก่าสุดจะตกหล่น)

## 7. รูปแบบข้อความ Discord ที่ระบบอ่านได้

ระบบอ่านจาก embed ของ Webhook (หรือเนื้อหาข้อความธรรมดา) โดยใช้ตัวอย่างลักษณะนี้:

```
🏆 Victory                       ← หรือ Defeat
Nightmare Train                   ← ชื่อแมพ (บรรทัดถัดจากผลลัพธ์ หรือ "Map: ...")
🎁 Rewards · 1
+ 9,625  Summer Pearls  → 85,756 ← "+จำนวน ชื่อไอเทม → ยอดรวมหลังได้"
💰 Balance
🪙1,482 💎24,339 ... 85,756      ← ยอดคงเหลือ
👤 Player
LiveKes45 · Level 245 [489/1808]
```

กฎการอ่านที่สำคัญ (ดู `parseMessage()`):
- **ผลลัพธ์:** พบคำว่า `victory`/`ชนะ` → Victory, พบ `defeat`/`loss`/`แพ้` → Defeat, ไม่เจอ → Unknown
- **แมพ:** ใช้ `Map:`/`Stage:` ก่อน, ถ้าไม่มีใช้บรรทัดถัดจากผลลัพธ์, ถ้าไม่มีอีกใช้ชื่อ embed, สุดท้ายเป็น `Unknown`
  ตัวอักษร Markdown (`**`, `## `) และแท็ก `<...>` จะถูกลบออก
- **รางวัล:** อ่านทีละบรรทัดตามรูปแบบ `+ จำนวน ชื่อ → ยอดรวม`
- **ผู้เล่น:** เอาข้อความก่อนเครื่องหมาย ` · ` (ตัดเลเวลออกตอนแสดงผล)
- **โหมด/ความยาก/เวฟ/เวลา:** จับจากคำว่า Raid/Story/Infinite/Challenge, Difficulty, Wave, Time
- **ข้อความที่ไม่บันทึก:** ถ้าไม่ใช่ห้อง/Webhook ที่ตั้งไว้, ส่งก่อนเวลาที่ล้างประวัติ, เป็น `Test notification`,
  หรือผลลัพธ์เป็น Unknown และไม่มีรางวัลเลย

ถ้าเปลี่ยนรูปแบบข้อความจากสคริปต์ Roblox ให้แก้ `parseMessage()` ให้ตรงกัน

## 8. วิธีที่ตัวเลขถูกคำนวณ

| ส่วนที่แสดง | มาจากไหน |
|---|---|
| **เพชร / ทอง** (ช่องหลัก) | ตัวเลขหลังไอคอน 💎 / 🪙 ในบรรทัด Balance ของรายงานล่าสุด |
| **SummerPearls / Trait Reroll** (ช่องหลัก) | ตัวเลขหลังลูกศร `→` ของรางวัลนั้นในรายงานล่าสุดที่มี |
| ช่องหลักเมื่ออ่านไม่ได้ | ใช้ยอดรวมรางวัลที่เก็บไว้แทน |
| **ของที่ได้ทั้งหมด** | รางวัลสะสมนับตั้งแต่ล้างประวัติครั้งล่าสุด (รวม "(Limited)" เข้ากับชื่อปกติ) |
| **อัตราชนะ / รอบ / ชนะ / แพ้** | นับจากทุกรอบในฐานข้อมูล |
| **ไทม์ไลน์ / กราฟ / อัตราต่อชั่วโมง** | อิงจาก 100 รอบล่าสุดที่โหลด |
| **อัตราต่อชั่วโมง** | ผลรวมในช่วง ÷ ชั่วโมงระหว่างรอบแรกถึงรอบล่าสุด (ซ่อนเมื่อข้อมูลน้อยกว่า 15 นาที) |

รอบที่ `Test notification` ถูกตัดออกจากทุกอย่าง (สถิติ ยอดไอเทม ไทม์ไลน์) เพราะเป็นการทดสอบ ไม่ใช่รอบจริง
ส่วนรอบ `Unknown` ถูกซ่อนเฉพาะในไทม์ไลน์ แต่ยังนับในสถิติและยอดไอเทม เพราะอาจมีรางวัลจริงอยู่
จึงมีหมายเหตุใต้การ์ดสถิติบอกจำนวนรอบที่ซ่อนไว้

## 9. API

ทุกเส้นทางต้องล็อกอิน (Basic auth) ยกเว้น `/health`

| เมธอด | พาธ | หน้าที่ |
|---|---|---|
| GET | `/health` | ตรวจสุขภาพ ตอบ `{"ok":true}` (ไม่ต้องล็อกอิน) |
| GET | `/api/dashboard` | ส่ง `stats`, `totals`, `runs` (100 รอบล่าสุด), `lastReport` |
| POST | `/api/clear` | ล้างประวัติทั้งหมด (ต้องส่งเฮดเดอร์ `x-confirm: clear`) |
| WebSocket | Socket.IO | เหตุการณ์ `updated` เมื่อมีข้อมูลเปลี่ยน |

## 10. ไอคอนและรูปแมพ

- ไอคอนไอเทมใน `public/assets/items/` และรูปแมพใน `public/assets/maps/` ดาวน์โหลดจาก
  **Anime Adventures Wiki (Fandom)** ลิขสิทธิ์เป็นของเจ้าของเดิม ใช้เพื่อแสดงผลในแดชบอร์ดส่วนตัวเท่านั้น
- การจับคู่ชื่อทำที่ฝั่งหน้าเว็บ: ตัดสัญลักษณ์และเปรียบเทียบแบบไม่สนตัวพิมพ์ มีไฟล์ `manifest.json` ในแต่ละโฟลเดอร์เป็นตารางชื่อ → ไฟล์
- ไอเทมที่ไม่มีไอคอนจากวิกิจะใช้ SVG สำรองใน `public/assets/` (Summer Pearl, Sky Portal ฯลฯ)
- ชื่อแมพที่ในเกมต่างจากวิกิมีชื่อแทนใน `maps/manifest.json`: `Sand Village`, `Fiend City`, `Haunted Academy`
- **ยังไม่มีรูป:** Rain Village, Spirit Town, Assassin Park (ไม่มีในวิกิ) แสดงเป็นกล่องไล่สีพร้อมชื่อแมพ

**เพิ่มรูปแมพเอง:** ใส่ไฟล์ภาพ (แนะนำ jpg กว้างราว 360px) ใน `public/assets/maps/`
แล้วเพิ่มบรรทัดใน `maps/manifest.json` เช่น `"Rain Village": "rain-village.jpg"` (ชื่อซ้ายต้องตรงกับชื่อแมพที่ขึ้นในรายงาน)
ไอเทมเพิ่มได้เหมือนกันใน `items/manifest.json`

## 11. ล้างประวัติ

  ยังไม่ได้แก้ (ต้องดูข้อความดิบจริงก่อน) และเมื่อแก้ parser แล้วอย่า reparse ย้อนหลังแบบนับรางวัลซ้ำ
- "Star Remnant" และ "Star Remnant (Limited)" ถูกรวมเป็นรายการเดียว แต่ไอเทมอื่นที่มีชื่อต่างกันเล็กน้อยจะแยกกัน
- ยังไม่ได้ทดสอบอัตโนมัติ (ไม่มี unit test) ตรวจด้วยมือและข้อมูลจำลอง

- **ห้าม** commit ไฟล์ `.env` หรือโทเค็น/รหัสผ่านใด ๆ ขึ้น GitHub (`.gitignore` กัน `.env` ไว้แล้ว)

## 15. คู่มือตั้งค่าตั้งแต่ศูนย์ (ทีละขั้น)

ใช้เมื่อต้องตั้งระบบใหม่ทั้งหมด (เช่น ย้ายบัญชี หรือสร้างใหม่หลังลบ) ถ้าระบบเดิมยังทำงานอยู่ **ไม่ต้องสร้างใหม่**

### 15.1 สร้างห้องและ Webhook ใน Discord
1. สร้างห้องข้อความสำหรับรับรายงานโดยเฉพาะ (แนะนำห้องส่วนตัว)
2. ตั้งค่าห้อง → Integrations → Webhooks → New Webhook → คัดลอก **Webhook URL**
3. นำ URL ไปใส่ในบอทฟาร์ม/สคริปต์ Roblox (ที่ช่องแจ้งเตือน Discord) และกด Test
4. เก็บ **Webhook ID** (ตัวเลขชุดแรกใน URL) ไว้ใช้กับ `DISCORD_WEBHOOK_ID`
5. เปิด Developer Mode แล้วคลิกขวาห้อง → Copy Channel ID เก็บไว้ใช้กับ `DISCORD_CHANNEL_ID`

### 15.2 สร้าง Discord Bot สำหรับอ่านห้อง
1. เข้า https://discord.com/developers/applications → New Application
2. แท็บ Bot → Reset Token แล้วคัดลอก **Token** เก็บเป็นความลับ (ใช้กับ `DISCORD_BOT_TOKEN`)
3. แท็บ Bot → เปิด **Message Content Intent**
4. แท็บ OAuth2 → URL Generator เลือก scope `bot` และสิทธิ์ View Channels + Read Message History
5. เปิดลิงก์ที่ได้เพื่อเชิญ Bot เข้าเซิร์ฟเวอร์ และตรวจว่า Bot เห็นห้องรายงาน

### 15.3 สร้างฐานข้อมูล (Supabase)
1. สร้างโปรเจกต์ PostgreSQL ใหม่ (เลือกภูมิภาคใกล้ตัว เช่น Singapore) และจดรหัสผ่านฐานข้อมูล
2. ปุ่ม Connect → เลือก **Session pooler** → คัดลอก connection string (รูปแบบ `postgresql://...`)
3. แทนที่ `[YOUR-PASSWORD]` ด้วยรหัสผ่านจริง ผลลัพธ์คือค่า `DATABASE_URL`
4. ไม่ต้องสร้างตารางเอง ระบบสร้างให้ตอนเริ่ม

### 15.4 Deploy บน Render
1. New → Web Service → เลือกรีโป GitHub ของโปรเจกต์ (branch `main`)
2. Runtime: Node · Build Command: `npm install` · Start Command: `npm start`
3. ใส่ Environment Variables ตามหัวข้อ 4 (ตั้ง `DASHBOARD_PASSWORD` เป็นรหัสผ่านยาวที่คิดเอง)
4. Create Web Service แล้วรอ build จนสถานะ Live
5. ดู Logs ควรเห็นข้อความตามลำดับ:
   - `Discord connected: <ชื่อบอท>`
   - `Dashboard listening on port ...`
   - `Discord history sync complete`

### 15.5 ตรวจว่าใช้งานได้
1. เปิด URL ของ Render ล็อกอินด้วยผู้ใช้ `admin` + รหัสผ่านที่ตั้ง
2. ส่งรายงานทดสอบจากบอทฟาร์ม (รอบจริงหรือปุ่ม Test) รอบ `Test notification` จะไม่แสดง ต้องรอรอบจริงจึงเห็นในไทม์ไลน์
3. มุมซ้ายบนควรเป็น "Connected" และมีตัวบอก "รายงานล่าสุด ... นาทีที่แล้ว"

## 16. โครงสร้างฐานข้อมูล

ระบบสร้าง 2 ตารางอัตโนมัติตอนเริ่ม (`CREATE TABLE IF NOT EXISTS`)

**`runs`** หนึ่งแถวต่อหนึ่งรายงาน

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `id` | TEXT (PK) | id ข้อความ Discord ใช้กันบันทึกซ้ำ |
| `created_at` | TIMESTAMPTZ | เวลาที่ข้อความถูกส่ง |
| `player` | TEXT | ชื่อผู้เล่น |
| `result` | TEXT | `Victory` / `Defeat` / `Unknown` |
| `map` | TEXT | ชื่อแมพ |
| `mode` | TEXT | Raid / Story / Infinite / Challenge |
| `wave` | INTEGER | เวฟ (อาจว่าง) |
| `duration` | TEXT | เวลาที่ใช้ |
| `difficulty` | TEXT | ความยาก |
| `weather` | TEXT | สภาพอากาศ |
| `rewards` | JSONB | รายการ `[{"amount":9625,"item":"Summer Pearls","total":85756}]` |
| `balances` | TEXT | บรรทัด Balance ดิบ ใช้อ่านเพชร/ทอง |
| `raw` | TEXT | ข้อความต้นฉบับ เก็บไว้ตรวจ/แก้ parser |

**`meta`** เก็บค่าระบบแบบ key/value ตอนนี้ใช้คีย์เดียวคือ `cleared_at` (เวลาที่ล้างประวัติล่าสุดเป็นมิลลิวินาที)

ตัวอย่างคำสั่งตรวจข้อมูลใน SQL editor ของ Supabase:

```sql
SELECT created_at, map, result FROM runs ORDER BY created_at DESC LIMIT 10;
SELECT result, COUNT(*) FROM runs GROUP BY result;
```

## 17. วิธีอัปเดตโค้ด

1. แก้ไฟล์ในเครื่อง (ส่วนมากอยู่ใน `public/` หรือ `server.js`)
2. ตรวจ syntax: `node --check server.js` และ `node --check public/app.js`
3. commit แล้ว push เข้า branch `main`
4. Render deploy อัตโนมัติ ดูสถานะในหน้า Events ของ Render
5. หลัง deploy เปิดเว็บแล้วกด Ctrl+F5 (ล้างแคช) เพื่อให้ได้ไฟล์ใหม่

ข้อควรระวัง
- อัปโหลดทั้งโฟลเดอร์ `public/` ให้ครบ (รวม `assets/`) ไม่งั้นรูปจะหาย
- อย่า commit `.env`, `node_modules/` หรือไฟล์ฐานข้อมูล (`.gitignore` กันไว้แล้ว)
- ถ้าแก้ `server.js` Render ต้อง restart ซึ่งทำเองอัตโนมัติหลัง deploy

## 18. คำถามที่พบบ่อย (FAQ)

**ทำไมเพชร/ทองเป็น 0?**
ระบบอ่านจากไอคอน 💎 / 🪙 ในบรรทัด Balance ถ้าสคริปต์ใช้อีโมจิอื่นจะอ่านไม่ได้ ดูวิธีแก้ในหัวข้อ 12

**ทำไมรอบทั้งหมดไม่เท่ากับจำนวนการ์ดในไทม์ไลน์?**
มีรอบที่ซ่อนไว้ (Unknown) ดูหมายเหตุใต้การ์ดสถิติ และหัวข้อ 8

**ยอด SummerPearls ไม่ตรงกับยอดสะสมในรายการด้านล่าง?**
ช่องหลักแสดงยอดคงเหลือจากรายงานล่าสุด ส่วน "ของที่ได้ทั้งหมด" คือผลรวมที่ได้หลังล้างประวัติ จึงต่างกันได้

**ล้างประวัติแล้วข้อมูลเก่ากลับมาไหม?**
ไม่กลับ ระบบจำเวลาที่ล้างไว้ในตาราง `meta` และข้ามข้อความที่เก่ากว่านั้น

**ปิดเครื่องคอมได้ไหม?**
ได้ เว็บและ Bot รันบน Render ส่วนสคริปต์ฟาร์มต้องรันบนเครื่อง/เกมที่ฟาร์มอยู่

**เว็บหยุดอัปเดตเวลาไม่มีคนเปิด?**
Render Free จะหลับ ตอนตื่นระบบอ่านย้อนหลังจาก Discord ให้ ถ้าอยากให้ตื่นตลอดต้องใช้แพ็กเกจเสียเงินหรือบริการ ping `/health`

**เพิ่มไอเทมใหม่ในช่อง 4 ช่องหลักได้ไหม?**
ได้ แก้ตัวแปร `slots` ใน `public/app.js` (ชื่อที่แสดง, รูปแบบชื่อไอเทมที่จับคู่ และไอคอน)

**เปลี่ยนเวลาเตือนตอนเงียบ?**
แก้ `STALE_MIN` ใน `public/app.js` (ตอนนี้ 40 นาที)

**ลืมรหัสผ่านเว็บ?**
เปลี่ยนค่า `DASHBOARD_PASSWORD` ในหน้า Environment ของ Render แล้ว redeploy
